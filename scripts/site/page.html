Dave · a Temper library

Agents, loops and a classroom clock, written once.

Dave is the library under Jam Pilot, a Phoenix app for school music lessons. It holds the OpenAI-style chat types, an engine that asks a model and lets the host check the answer, the two loops Jam Pilot runs on it (score repair and a composer's assistant), a generic agent with a pluggable specialty and tool buckets, and the clock that keeps a TV and thirty iPads on the same beat. It is written once in Temper and translated to C#, Java, JavaScript, Lua, Python, Rust and Elixir. Jam Pilot runs the Elixir translation on its server and the JavaScript one in every browser.

Every code block on this page is cut from a real file by the build script, library and host alike. The demos run the library's own JavaScript build in this browser with scripted model replies: no model is called, every step is real.

src/chat

The wire format, with the network left to the host.

The chat completions format is the OpenAI one because every other provider speaks it. Messages are a sealed type, a tool call keeps the model's arguments as the JSON text it produced, and a request carries an extra map merged into the top-level object as given, which is how a host sends reasoning_effort. The one interface the host implements is Transport: one synchronous method, and a 4xx or 5xx is a response, not a failure.

{{snippet:transport}} {{snippet:client}}

Messages

A sealed interface translates to a sum type: a Rust enum, a C# class hierarchy, a when in Temper. A host never meets a bag of nullable fields that only make sense in some roles.

{{snippet:messages}} {{snippet:toolcall}}

Problems

Temper's Bubble carries no message, so a decoder that cannot accept its input records why, with the JSON path, before it bubbles. Nothing is defaulted silently.

{{snippet:problems}}

Streaming

The assembler takes frames, not lines, because a socket read ends wherever it ends: the unfinished last line waits in a buffer for the next frame. finish() builds the same ChatResponse a whole reply gives, usage included. This replaced Jam Pilot's hand-written SSE parser; a malformed data line is now a problem that bubbles, not a line that is skipped.

src/rounds

The engine: ask, read, check, send the problems back.

A rounds loop asks a model for something, reads the reply into a candidate, has the host check it, sends the problems back, and stops after N rounds. The host asks next(event) and performs the step it gets. These two sealed types are the whole vocabulary between the library and a host:

{{snippet:steps}}

What differs between loops is plugged in, and nothing else is: a policy, a script (the turns the model hears and the sentences the record keeps) and a reader (the reply as a proposal, the proposal as the text to check).

{{snippet:policy}}

The engine's next is a when over the event. A CheckPassed with no Check outstanding is the host's bug and panics.

{{snippet:next}}

Tool turns

A loop may offer tools, in buckets. A reply that calls them is a RunTools step inside the round; the host's results come back as tool messages, in the calls' order whatever order the host reported them in, and the model is asked again. After the round's budget of tool turns the tools are closed with tool_choice: "none" and a turn asking for the answer. A call to a tool in no offered bucket never reaches the host.

{{snippet:buckets}} {{snippet:tool_turn}}

src/repair

    
Repair: the smallest edits that make the reader take the score.

    
When Jam Pilot's strict reader refuses an imported score, the model is asked for find/replace edits, three rounds at most, a cut-off retried once at low effort, a reviewer's note as a tie-breaker on retry. The turns are byte for byte what the host sent before the engine existed, because every error sentence goes back to the model as its next turn and was tuned against it.

src/compose

    
Compose: a whole song back, five rounds, the draft kept.

    
A teacher types a song as text and asks the bot in plain words. The reply is a Summary: line and the whole song in a fence. The host's reader checks what comes back, then its word list; a song that does not read goes back with the reader's own sentences. The last song that read is the draft: when the rounds run out it is handed back anyway, problems and all. The effort schedule is a measurement: at "medium" and 8,000 tokens the model thought through all 8,000 and never answered.

src/room

    
The room: one clock on the server, a follower on every screen.

    
The classroom plays from a TV while every child follows on an iPad. The server holds one clock per score; each page keeps a follower that reads the broadcasts through its own estimated offset. A play can hold at the top of a bar for the count-in, and the words "1, 2, ready, play" come from the bar's length. Nothing here reads a clock: every method takes milliseconds from the host, so the Elixir server and the JavaScript pages run the same arithmetic. Before the port the formula lived twice, and the day the count-in shipped the two copies disagreed: the red line wobbled on every heartbeat.

Server side: the GenServer that owns the clocks

    
Time, the broadcast and the heartbeat are the host's. Temper objects in Elixir live in the process dictionary and nothing frees them on its own, so the server collects the heap after every call with the live clocks as roots. The channel answers pings with its wall clock, which is all a follower needs.

Tests and backends

    
Seventy tests, extracted into seven frameworks.

    
Tests live beside the code as test blocks and each backend extracts them into its own framework: mocha, pytest, cargo test, MSTest, ExUnit. Every check runs inside a function that takes the Test, with inputs fed through a list, because the Temper frontend folds calls whose inputs are all literals and would otherwise test the compiler's interpreter instead of the generated code.

The matrix script runs the suite on every backend and writes the table; a backend that fails to run at all is "no run", never a pass.

What the backends taught

    
    
      
  • The C# backend turns an if used as a when arm into a dangling else; the Rust backend types [new TextPart(x)] as Vec<TextPart> where a Vec<ContentPart> is needed; the JS backend drops a std function from the extracted test file when the test file re-imports it. Each has a kept probe under probes/.
    • 
      
  • A field named finish beside a method finish() reads as the method on interp and as the field on js and py; the assembler's field is finishSeen.
    • 
      
  • The Elixir backend puts every class of every module into one namespace, test helpers included, and the last one wins: two test files each declaring class Run pass on six backends and fail on Elixir with Run.new/3 is undefined. Helpers carry their module's name.
    • 
      
  • The Elixir backend emits only the full-arity constructor, so host call sites pass every argument, defaults included.
    • 
      
  • Float64 division can bubble, so a non-throwing function multiplies by 0.5 or writes orelse panic(); the Elixir CLI rejects a for..of that reassigns an outer variable, so the room uses indexed loops.
